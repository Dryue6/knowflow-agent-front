[2026-05-23] 聊天回答流式渲染优化
- 修改内容：将聊天页 SSE 响应解析从等待完整事件块改为按行增量消费 `message` 事件的 `data:` 内容，使后端在同一个 `event:message` 中连续推送多行数据时，前端也能边接收边追加 agent 回复；同时保留 `userMessageId`、`assistantMessageId` 和 `citations` 等元数据事件在事件结束后统一提交。
- 注意事项：后端仍需以换行刷新 `data:` 行；若服务端或代理层缓存整段响应，前端无法突破网络层缓冲限制。多行 `message` 会按 SSE 语义补回换行，以保持段落格式。

[2026-05-23] 修复流式回答结束后对话消失
- 修改内容：为正在发送消息的会话增加流式状态保护，历史消息加载遇到当前流式会话时不再覆盖页面消息；流式结束后仅刷新会话列表，不再立即调用历史消息接口替换刚刚通过 SSE 渲染出的问答内容。
- 注意事项：本轮问答展示依赖 SSE 返回的 `userMessageId`、`assistantMessageId`、`message` 和 `citations` 事件；刷新页面后的历史记录仍由后端消息历史接口提供，后端需要确保最终持久化内容完整。

[2026-05-24] 调整聊天回答完成后的滚动锚点
- 修改内容：将聊天页自动滚动目标从消息列表底部调整为最后一条助手消息正文尾部，并在助手正文内增加不可见锚点；流式正文更新和回答结束后优先滚动到该锚点，避免引用卡片渲染后页面自动跳到引用区域。
- 注意事项：底部滚动锚点仅作为没有助手正文锚点时的兜底；引用卡片仍保留在正文下方，用户需要手动继续向下滚动查看引用详情。

[2026-05-24] 修复下方引用缺少具体位置

- 注意事项：若后端后续补充 `pageNumber`、`sectionTitle` 或 `paragraphIndex`，前端会继续优先展示这些结构化位置，并同时保留片段 ID 作为精确回查依据。

[2026-05-24] 修复流式正文显示不全
- 修改内容：固定每次助手消息状态更新的目标消息 ID，避免 React 批量更新时读取到已变化的 `assistantMessageId` 导致正文分片写入失败；SSE 完成后使用累计的完整正文再校准一次助手消息内容，兼容本地临时 ID 与后端返回 ID 的切换时序。
- 注意事项：该修复不改变后端 SSE 协议；若后端 Network 响应或历史消息接口本身已缺失内容，需要继续从后端生成或持久化链路排查。
